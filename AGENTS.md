# AGENTS.md — Haunted Phonograph

This repository is a new appliance. Preserve its constitutional seams before adding capability.

## Accepted execution chain

```text
canonical source
→ admitted observations
→ PhonographScore proposal
→ deterministic mutation
→ ResolvedPerformance
→ projection/export
→ receipt
```

Do not bypass or quietly fuse these stages merely because a library API makes it convenient.

## Authority law

- Source-derived claims are **evidence**, not composition.
- Incomplete source-derived claims remain **uncertainty**.
- Newly generated musical material is **proposal**.
- A proposal must never be relabeled as source evidence because it is plausible or musically useful.
- Export formats are projections, not canonical authority.

## Determinism

- No hidden entropy.
- Any stochastic behavior must come from an explicit, named seed/stream that can be recorded and replayed.
- Deterministic mutation tests should prove replay across meaningful durations and structures, not only toy one-event cases.

## Resolution boundary

Renderers/exporters consume `ResolvedPerformance`-equivalent state. They must not independently perform harmony inference, composition, structural mutation, or source interpretation.

If MIDI and audio renderers disagree, repair the shared resolved musical state rather than teaching each renderer a separate musical truth.

## Uncertainty and refusal

Do not fabricate precision to keep the pipeline moving. Unknown chord quality, beat position, note identity, section boundary, instrumentation, or other source fact may remain unknown.

A degraded but truthful specimen is preferable to a confident counterfeit.

## Compatibility discipline

Before importing code or abstractions from Haunted Toaster, Toaster Lab, Band Runtime, TranchNode, Project0, or another Collective repository:

1. identify the semantic contract being reused;
2. preserve this repository's authority boundaries;
3. prefer shared laws and small compatible primitives over wholesale architectural transplantation;
4. do not create a dependency merely to express family resemblance.

## Proof before completion

A feature is not complete because it generated attractive audio.

Where applicable, prove:

- source identity is stable;
- evidence/proposal provenance survives resolution;
- mutation is replayable from recorded state;
- exporter output corresponds to resolved state;
- output hashes are receipted;
- uncertain evidence is not promoted silently;
- failure does not leave misleading successful artifacts.

## Scope rule

Prefer vertical musical specimens over broad infrastructure.

For the first milestone, one source → one bounded observation set → one small score → one mutation → one MIDI file → one receipt is enough if the semantics are real and tested.
