# Haunted Phonograph Specimen 001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one command that transforms a real checked-in WAV plus bounded admitted observations into deterministic new musical material, a renderer-neutral `ResolvedPerformance`, a playable Standard MIDI File, and a provenance receipt.

**Architecture:** Keep the authority chain explicit in small modules. Source and observation modules admit evidence; score/mutation/performance modules create and resolve proposal state; the MIDI module projects only resolved events; the runner writes artifacts and creates a success receipt only after MIDI export succeeds. Reuse `src/provenance.mjs` as the sole evidence/uncertainty/proposal authority primitive.

**Tech Stack:** Node.js 22+, ES modules, built-in `node:test`, `node:crypto`, `node:fs/promises`, `Buffer`; zero production dependencies; Standard MIDI File Type 0.

## Global Constraints

- Required chain: `canonical source → admitted observations → PhonographScore proposal → deterministic mutation → ResolvedPerformance → Standard MIDI File → receipt`.
- Use a real checked-in PCM WAV, but do not infer semantic facts automatically in Specimen 001.
- Source-facing semantic claims must enter through the landed provenance contract.
- Preserve explicit uncertainty; do not fabricate harmony/key/chord precision.
- Implement exactly one mutation law: `interval-preserving-motif-displacement/v1`.
- No hidden entropy, wall clock, random API, machine identity, model call, network, audio analysis, or external package dependency.
- Exporters consume only `ResolvedPerformance`; they do not inspect source/observations/score or make musical decisions.
- A success receipt must not exist when MIDI export fails.
- Default command: `npm run specimen:001`.
